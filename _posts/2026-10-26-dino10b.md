<nav class="dino10b-tabs"><a href="/blog/dino10b/" class="active">Blog post</a><a href="/blog/dino10b/readme/">README</a></nav>
<p><strong>Swann Bessa, Matthijs Douze, Hervé Jégou</strong></p>
<p>Dino10B is a benchmark for clustering and nearest-neighbor search at ten-billion-vector scale: deduplicated, shuffled, byte-quantized DINOv3 [<a href="#ref1">1</a>] patch descriptors from Creative Commons images, released as nested subsets from 100k up to 10B vectors.</p>
<p><img alt="An image, cropped into 14x14 patches, run through DINOv3, producing 196 1024-dimensional vectors." src="/assets/dino10b-pipeline.png" /></p>
<p><em>How DINO embedding vectors are made.</em></p>
<h2>Dataset characteristics</h2>
<ul>
<li><strong>10,000,000,000</strong> vectors, 1024-d, uint8, L2 distance</li>
<li>16 nested subsets from <strong>100k to 10B</strong>, each a prefix of the next: 100k / 200k / 500k / 1M / 2M / 5M / 10M / 20M / 50M / 100M / 200M / 500M / 1B / 2B / 5B / 10B</li>
<li><strong>100k held-out queries</strong> (<code>queries_clean.bvecs</code>) with exact top-10 ground truth at every subset size</li>
<li><strong>99M training queries</strong> (<code>train_queries_99M.bvecs</code>), held out separately</li>
</ul>
<h2>Using it</h2>
<p>We provide instructions below for using Dino10B. More detailed instructions are in the dataset's README.md, which you can read in the <a class="ext" href="/blog/dino10b/readme/">README</a> tab of this site.</p>
<p>Downloading and loading are two separate steps: the data must be on disk before anything can read it.</p>
<p><strong>Step 1 — download:</strong></p>
<ul>
<li>Install axel from its official repository, <a class="ext" href="https://github.com/axel-download-accelerator/axel">github.com/axel-download-accelerator/axel</a>. It is much faster than a single connection.</li>
<li>Copy <a class="ext" href="/blog/dino10b/readme/#download-script">our download script</a> and run it with <code>bash</code> from inside a <code>data/</code> folder in your working directory. It fetches <code>file_list.txt</code>, then every file it lists, into <code>data/dino_vitl_10B/</code>. By default we set 16 connections for axel. You may want to change it.</li>
<li>Without axel, use <a class="ext" href="/blog/dino10b/readme/#download-script-wget">the wget version</a> just below it in the README. That works, but expect days rather than hours for the full 10.3 TB.</li>
<li>To download only part of the dataset: download <code>file_list.txt</code> on its own and delete the lines you don't need, then run the script without its first line, which would download the full list again. The base vectors are 50 chunks of 200M vectors each (<code>chunk_0000.bvecs</code> ... <code>chunk_0049.bvecs</code>).</li>
</ul>
<p><strong>Step 2 — load it, only once step 1 has finished:</strong></p>
<ul>
<li>Via faiss. Its <code>DatasetDINO10B(nb=...)</code> constructor requires you to have the data in a <code>data/</code> folder in your current working directory, so run your script from the directory that contains <code>data/</code> (or symlink <code>data/</code> there): <pre><code>from faiss.contrib.datasets import DatasetDINO10B
ds = DatasetDINO10B(nb=10_000_000_000)  # any of the sizes listed above</code></pre></li>
<li>Standalone, without faiss — a separate loader script, <code>code_dataset_dino.py</code>, <em>does</em> take an explicit <code>path=</code>. This script is itself one of the files listed in <code>file_list.txt</code>; see the README tab. <pre><code>from code_dataset_dino import DatasetDINO10B
ds = DatasetDINO10B(nb=1_000_000, path="path/to/dino_vitl_10B")</code></pre></li>
<li>Neither loader downloads anything itself — both just read what step 1 already put on disk.</li>
</ul>
<p><strong>One gotcha:</strong> each chunk holds exactly 200,000,000 vectors. A batch size that doesn't divide 200M straddles two chunks and pays a real concatenation cost — pick a divisor of 200M. We use 1,000,000 (faiss doesn't impose a default).</p>
<h2>The case for 10-billion-scale datasets</h2>
<p>Billion-scale datasets have been the standard for over a decade. One billion was a pragmatic ceiling: big enough to matter, small enough for one machine. That ceiling no longer matches the hardware. A modern server holds hundreds of gigabytes of RAM and terabytes of SSD, so ten billion vectors on one machine is now realistic.</p>
<p>Dino10B isn't the only dataset at that scale — Qdrant's FineWeb-10B [<a href="#ref2">2</a>] also reaches ten billion vectors, in text. Dino10B is built from images instead.</p>
<h2>How we built the dataset</h2>
<p>We run a DINOv3 [<a href="#ref1">1</a>] ViT-L/16 over images from YFCC100M [<a href="#ref3">3</a>], a Creative-Commons Flickr collection. Each image becomes a 14×14 grid of patches, each patch a 1024-dimensional vector — one feature per patch, nothing hand-crafted. Roughly 60M images get us past 11.7B raw vectors, with margin for what gets dropped next.</p>
<p><img alt="Deduplicating and shuffling the raw patches." src="/assets/dino10b-shuffle.png" /></p>
<p>Raw patches from the same image are highly correlated, so a plain scan drifts over time. We quantize each vector to one byte per dimension, then deduplicate (hash every quantized vector, keep one copy) and shuffle block-by-block, since the whole corpus is too big to hold twice in RAM. What's left: 10B vectors, i.i.d., no duplicates, ~10.3 TB on disk.</p>
